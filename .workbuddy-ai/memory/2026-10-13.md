## 13.12 — the dock's band is reserved, and the panel gives up the difference

Requested: "can you fix on timeline it collison with navbar bottom maybe on
container section about width its like in experience section", with a screenshot
of the workstation's footer sitting under the quick navigation. Full record in
`docs/arrangement-hero.md` §13.12.

**The width suggestion was a dead end — say so next time rather than trying it.**
The dock is `fixed` (20px off the bottom, 56px tall, so it owns the bottom 76px)
and *centred*, 256px wide. The panel is top-aligned in the deck with a content
height, so its bottom edge is `deckTop + 552.5` at every viewport. Narrowing the
About container to the experience section's `min(1050px, 100%)` moves the panel's
left edge 644 → 679 against a dock at 627…885: still 206px of horizontal overlap,
and the panel gets *taller* because its readout sentence wraps.

**The real bug: nothing in About knew the dock existed.** Measured before the fix
at 1512×784 (the reporter's window — 1920×993 screenshot at 1.27 scale):
panel `172.3 → 724.8` vs dock `708.6 → 764.6`, **16px of overlap across 241px of
the dock's width**, straight across the "CLIP nn / SELECTED" readout. 58px at
1280×720. Nothing above ~800px tall collided, which is why earlier passes at 900
and 982 all passed. **Lesson: when a collision is reported, sweep viewport
*heights*, not just widths — 784 and 720 were never in the set.**

**Fix, two halves.**
1. `padding-bottom: calc(76px + max(0px, 620px - 100svh))` on
   `.aboutSeam .aboutDeck`. Padding and not a shorter seam because the deck is
   `flex: 1` — its border box is the stage's leftover either way, so
   `offsetHeight` does not move, and `offsetHeight` is what the read measures its
   travel from. The travel stays exactly −194px at 1440×900.
2. `max-height: 100%` on the panel (resolves against the grid area = the space
   above the dock) + a flex chain so the difference is *distributed* rather than
   clipped. A `max-height` on a block would just clip, and the first thing off
   the bottom is the readout the rule exists to protect.

**The correction that mattered: `flex: auto` was wrong.** The first pass let the
panel lose 42px at *every* viewport, including 1728×1117 where nothing collided.
An auto-height grid resolves `1fr` rows to max-content, and a lane's max-content
is its content (89px), not the 104px it is drawn at. The basis must be written
out: `flex: 1 1 calc(34px + 3 * 104px)` with `min-height: 0`.

**Below ~780px tall the lanes reach their floor (89px, a track header) and the
third crops mid-clip**, so a `@media (min-width: 769px) and (max-height: 780px)`
block sheds 49px of chrome (brand 58→44, header padding 5px, track header 9px,
readout 8px). Nothing dropped, nothing hidden.

**Two near-misses worth remembering.**
- The phone's `display: none` on the panel is `.timelinePanel` — one class
  *lighter* than the `.aboutSeam .timelinePanel { display: flex }` this added to
  the same box. The seam would have won and the panel would have come back on the
  one viewport it is never drawn on. Needed an explicit `.aboutSeam .timelinePanel
  { display: none }` in the phone query. **Same class as §13.7/§13.10: a
  declaration that is right in one layout state silently out-specifies the rule
  that was handling another.**
- The flow fallbacks (phone / reduced motion / no JS) had to undo the whole
  thing: no deck content box to cap against, and the reserved band would be 76px
  of dead space under the last card.

**Verified** (five progress points per viewport): overlap 0 at 1728×1117,
1512×982, 1440×900, 1512×784, 1280×720; panel keeps 552.5px and 104px lanes at
1440×900 and above (main's height), shrinks to 518.5/92.7 at 784 and 479.1/88.2 at
720, both with zero arrangement overflow. Phone: panel `display: none`, height 0,
no dead padding. Reduced motion: `display: block`, parks at `63 → 615.5`. tsc
clean, prettier clean on the touched file, 139/139 Jest.

**Sandbox note, unchanged from yesterday:** `node <script>` in the workspace dies
with exit 1 and no output; copy the script into `node_modules/` and run it from
there, retried in a loop (flaky, ~1 in 3). `npx` needs the network — use
`./node_modules/.bin/<tool>`.

## DAW redesign — applying `arrangement-hero-daw-redesign.patch`

Requested: "@…/arrangement-hero-daw-redesign.patch can you apple redesign hero
section above". Full record in `docs/arrangement-hero.md`, the `## Redesign`
section and its two `###` subsections.

**What the redesign is.** The hero is now a DAW playlist: toolbar (brand, site
nav as the menu, a stop/play transport, two LCDs), a two-row ruler (stage markers
over bar numbers 1–32), track headers that step out during the dive, clips with a

technology, fader at its listed level). `OPEN_SCALE` 1.28 → 1 so the open frame is
the whole arrangement. New file: `arrangement-mixer.tsx`.

**The patch would not apply — `git apply --3way` fixed it.** It was cut against
the §13.7-era tree, so both `docs/arrangement-hero.md` and
`use-arrangement-hero.ts` came back "patch does not apply". Every base blob it
names (`8df2dca`, `04f711e`, `cf028eb`, `255a1fc`, `741e7dc`, `41566dd`,
`d0441d5`, `0c28d8c`, `3a425c3`, `f943f28`, `b35ec50`) was still in the object
store, so the 3-way merge worked and only those two files conflicted. **Both
conflicts were "this branch grew material the patch never saw", and both sides
were additions, so both were kept** — the About read's three locals and the
toolbar's position readout in the hook, and §13.11/§13.12 ahead of the patch's new
`## Redesign` heading in the doc.

**The patch carried a regression: `styles.rulerLive` → `undefined`.** The ruler's
`live` prop selected `.rulerLive`, and the patch deleted that rule (every `.tick`
now reads the camera's transform directly, so there is no static rule left to
switch away from). The prop outlived the class it named, so the element shipped
`class="ruler undefined"`. **Found by diffing the served HTML against the source**
— and confirmed as a deletion rather than a name that never existed by checking
`git show HEAD:…module.css`, where `.rulerLive .tick` is at L145. Fixed by
dropping the prop and its call site. **Lesson: after applying someone else's
patch, sweep every `styles.X` reference against the class names the CSS module
actually defines — a deleted rule leaves no error, only a literal `undefined` in
the DOM.** The same sweep found `clipSelected` dangling, but that predates this
pass and is inert behind `.filter(Boolean)`.

**The "stalling readout" was a bad probe, not a bug.** Scrolling by *page*
fraction made the LCD look frozen at `022:02` from a quarter of the way down —
because the hero is 3240px of a 11772px page, so everything past the first quarter
reads a finished arrangement. Re-probed inside the hero's own range and it walks
`001:01 → 010:02 → 021:04 → 022:02`. The stop is correct: the playhead walks
`mix(0, profileCentre, f)` and parks on the profile clip's centre, `0.67 × 32 =
21.44` = bar 22 beat 2. The ruler counts 32 because the arrangement is 32 bars.
**Lesson: scroll a pinned section by its own `offsetHeight − innerHeight`, never
by document fraction.**

**Verified.** Geometry at 8 viewports (769→1920): zero horizontal overflow, no
toolbar self-collision, the name fits its clip, 32 bars, 85 strips. Phone 390:
in flow, no overflow, head label inside the clip. Reduced motion 1440×900: no

## 14.20 — Hero + About immersive scroll: the contract, implemented and verified

Requested: "can you implement and execute completely and read carefully the docs
@docs/HERO_ABOUT_IMMERSIVE_SCROLL.md". The doc is the implementation contract for an
immersive Hero → About scroll: slat preloader, one-run landing gate, camera overshoot
plus a depth layer, a retimed hero chapter, and About rebuilt as a channel rail. All
six sections are implemented.

**New files.** `components/ui/slat-count-preloader.tsx` and its
`slat-count-preloader.module.css` — the contract referenced a "supplied" component
that did not exist, so it was written from scratch, with the pure schedule helpers
exported so the boot is unit-testable.
`features/landing-page/components/landing-gate.tsx` (sessionStorage key
`aditya-landing-session-boot`, one boot per session). `tests/slat-count-preloader.test.ts`
and `tests/style-mock.js` (so a component importing a CSS module loads under jsdom).

**Two real bugs found by verification, both fixed.**

1. **The About collapse gate was missing the breakpoint.** It was gated on
   `(prefers-reduced-motion: no-preference) and (scripting: enabled)` only, but below
   769px `arrangement.module.css` drops `.stage` to `position: static` and takes the
   camera away — so at 390 and 768 two of three About channels were `display: none`
   with *nothing driving the selection*. Both the component docstring and the CSS
   comment claimed the gate was "the same conditions that pin the seam". It was not.
   Fixed with `and (min-width: 769px)`. **Lesson: a comment that states an invariant
   is a test you have not written.**

2. **The critical-CSS inliner never rebased relative `url()` (pre-existing).**
   `scripts/inline-critical-css.mjs` copies `@font-face` rules into an inline `<style>`,
   where `url(../media/x.woff2)` resolves against the *document* (`/`) instead of the
   sheet's directory. Every self-hosted face 404'd at `/media/...` and was re-fetched
   when the linked sheet landed: five wasted round trips on the critical path and a
   visible font swap. Fixed with `rebaseUrls(css, href)`, applied per sheet before the
   rules are split; only genuinely relative URLs are touched (data / http /
   protocol-relative / fragment / absolute and escaped forms come back byte-for-byte).
   Verified: 26/26 `url()` refs in the built inline block are now absolute, 0 relative,
   font returns 200.

**One deliberate deviation from the contract's snippet.** §3's `cameraScale` ends at
`zoomScale − 0.025`, contradicting its own sentence "the final value returns to the
measured fit". Implemented instead as a half-sine bump (`weight * 0.025 * zoomScale`)
spent 0.84 → 0.91, which is exactly zero at both ends, so `cameraScale(1, z) === z`
holds to the last decimal. Measured in-browser: `final=2.000` against `fit=1.998`
(world 1165 / clip 583), peak ratio 1.0222, settling flat.

**Verification, all green.** `pnpm build` OK (`5 stylesheet links + 236KB inline
critical CSS`). Jest **162/162** over 8 suites. eslint clean on every changed file —
only two pre-existing warnings remain (unused `ScrollTrigger` in `hero-chapter.ts`,
`exhaustive-deps` in `use-arrangement-hero.ts`). Browser suite **94/94** at
