## Sound becomes matter — the Patch retires, About becomes a real section

Owner: *"can you implement `docs/sound-becomes-matter-design.md` completely,
you read carefully and execute all"*. Branch **`feat/sound-becomes-matter`**,
on top of `docs/arrangement` @ `655d6a3`. **Not committed** — no approval given.

The design is a handoff: the DAW hero is "a picture of a machine", and this
carries the reader out of the device into an open editorial biography. New
`features/landing-page/components/matter/`:

- **`matter-frame.ts`** — the whole choreography as one pure function,
  `matterFrame(progress, geometry) → numbers`. No DOM, no GSAP, no timers. That
  is what lets `tests/matter-frame.test.ts` (24 tests) pin every phase boundary
  against a written-out fixture with no browser. Exports `MATTER_PHASES`
  (`depart`, `spread`, `signalIn`, `swap`, `arrive`), `MATTER_SCALE_CEILING = 8`,
  `MATTER_READING_AT = 0.8`, `MATTER_CONTOUR_TRAVEL = {far:8, middle:20, near:40}`.
- **`use-matter-motion.ts`** — imports GSAP/ScrollTrigger *inside* the activation
  path behind a plain `matchMedia` listener, so phones and reduced motion never
  download them. **No second Lenis** — `use-rack-animations.ts` owns the page's
  one smoother and one ticker.
- **`matter-bridge.tsx` / `matter.module.css`** — decoration is opt-in
  (`display:none` until `data-motion="ready"`); the biography is a real
  `<section id="about">` in ordinary flow and is the only `#about` on the page.

### The one that nearly shipped broken

**`gsap.quickSetter(target, 'scale')` throws.** GSAP routes the `scale`
shorthand through a `scaleX,scaleY` *style* write, and a comma is not legal in a
CSS property name, so it raises `InvalidCharacterError` instead of scaling.
`x`, `y` and `opacity` quickSetters are fine; `gsap.set(el,{x,y,scale})` is fine.
The proxy's translate and scale are now **one direct `style.transform` string**
and no longer touch quickSetter. A handoff whose only scale silently throws is a
handoff that never runs — worth remembering, because the failure is a throw
inside a scroll callback and is easy to mistake for "the animation is subtle".

### Two things that look like bugs in a probe but are not

- **GSAP writes the `transform` ATTRIBUTE for SVG elements**, not
  `style.transform`. Reading `.style.transform` on the contours returns `null`
  and looks like the parallax is dead. Read `getAttribute('transform')`.
- **`data-motion` is set before `measure()`**, so a missing `data-motion` means
  the setup never ran at all — not that the maths is wrong.

### Defect 2 — the machine was replaced by a flat field (the real one)

With the clocks merely *met*, scroll 3240 showed the whole DAW machine and 3300 —
60px later — showed a flat `#14171a` field with the same cream band. A cut.

The design is explicit and the implementation was violating it:

- line 249 — `0–.15 Recognize — **Hero holds**; source signal is clear.`
- line 250 — `.15–.42 Leave device — Signal proxy expands; **hardware recedes and exits.**`
- line 44 — `**DAW chrome disappears outside viewport through scaling/clipping**`

**The machine cannot hold, and that is structural, not a tuning problem.** The
hero's trigger is `start:'top top'` → `end:'bottom bottom'`, and the section is
one viewport of sticky stage plus the camera's travel — so the camera's last
frame and the stage's last *pinned* frame are the same frame. One scroll past it
the machine is sliding away. A cross-fade needs both things present; the bridge
had nothing to dissolve *from*.

### The fix — a hold the two sections share

The bridge already had `deviceOpacity` ("the outgoing device leaving the frame")
and the hero already marked `[data-matter-device]`. They were dead code in
practice because the device was off-screen by the time they ran.

1. `matter-frame.ts` — new `stageOpacity` (0 → 1 across `MATTER_HOLD`) and
   `MATTER_HOLD = MATTER_PHASES.depart[0]`. Deliberately the *top of `depart`*,
   not a number of its own, so the takeover and the departure meet at one
   boundary.
2. `use-matter-motion.ts` — publishes `--arr-hold` = `MATTER_HOLD × (bridgeHeight
   − 100svh)` on `document.documentElement`, and writes `stage.style.opacity`
   instead of a `visibility` flip.
3. `arrangement.module.css` — `.hero { height: calc(var(--arr-scroll) +
   var(--arr-hold, 0px)) }`. Unset everywhere the motion query fails, and the
   phone / reduced-motion rules already set `height: auto` later in the file.
4. `use-arrangement-hero.ts` — the camera now states **its own** travel
   (`section.offsetHeight − stage.clientHeight − hold`) instead of inheriting
   `bottom bottom`, so growing the section no longer retimes the dive.
5. `matter.module.css` — `.stage { visibility: hidden }` deleted (the hook's
   opacity is the whole mechanism now).

### The bug I introduced, and the shape of it

First attempt grew the hero by the hold but left the pull-up at `-100svh`. The
probe caught it immediately:

## Follow-up audit: the practice-landing scene was empty (user report)

User: "the result is still bad especially in scene show text from Start with the
user. is not have rich component".

**How I actually looked at it this time.** Playwright (already a devDependency)
against a real dev server, sampling the bridge's own progress range and reading
back computed styles. Two environment traps worth remembering:

- **`next dev` blocks `127.0.0.1` as a cross-origin dev resource.** Loading the
  page at `http://127.0.0.1:3000` silently breaks hydration: no React fibers are
  attached, `data-motion` never gets set, the stage stays `display: none`, and
  the whole decorative layer is invisible. It looks exactly like a real bug.
  Use `http://localhost:3000`. (`allowedDevOrigins` in `next.config.mjs` is the
  alternative.)
- **The managed node (`~/.workbuddy-ai/.../22.22.2-6/bin/node`) exits 1 with no
  output in this sandbox.** `/opt/homebrew/bin/node` (v24.5.0) works. Use it for
  jest/eslint/tsc/playwright scripts, e.g.
  `/opt/homebrew/bin/node node_modules/jest/bin/jest.js`.

**The measured defect.** At `p=.80`, where `Start with the user.` is legible,
the stage was: `deviceShell` opacity 0, `practiceResidue` 0, `proxy` 0,
`ground` 0 — only 3 hairline contours and the resident `playhead` remained. The
sentence landed on an empty field.

Root cause is a phase error, not an artwork error. The plan's prose puts the
first practice line at `p≈.65`; measured at 1440×900 it arrives at `p≈.78–.80`,
because the panel's own top padding and the `Behind the interface.` title sit
*above* the practice statements. The residue was keyed to `release`/`clear`
(peak `.22` at `p=.70`, zero at `p=.80`) — so it peaked the frame before the
heading arrived and vanished on the frame it arrived.

**Fix.** `matter-device.ts` gains `MATTER_RESIDUE_PHASES` (`in: [.52,.74]`,
`out: [.82,.94]`), decoupling the residue from the shell's `clear`;
`MATTER_RESIDUE_FLOOR` 0.22 → 0.30 (0.22 was under the legibility threshold once
the residue is the only thing in the band). `matterDeviceState` reading states
now end on the residue's exit. The residue artwork in `matter-bridge.tsx` was
rebuilt from 2 hairline paths to a 13-element turntable fragment (platter with
grooves/label/spindle/groove-mark, tonearm, 3-bar meter) at the shell's own
geometry; `matter.module.css` recolours it from `--primary` to the machine's ink
with the accent reserved for spindle/stylus, moves it `top: 16% → 2%` and
`min(18rem,26vw) → min(23rem,28vw)` so it clears the panel when the heading
lands. Verified: residue box (820,18,368,184), fully clear of the panel at
`p=.76`/`.80`.

**Separate real bug found, NOT fixed (out of scope).** `app/layout.tsx:177`
ships `try{if(location.pathname!=='/'||location.hash==='#about')return;...}catch(e){}`.
A bare `return` at the top level of a classic inline script is a *parse-time*
SyntaxError and `try/catch` cannot catch it, so the script never runs and
`data-interface='hidden'` is never set — the exact defect its own comment says
it exists to prevent. Confirmed in-browser: "Uncaught SyntaxError: Illegal
return statement", filename = the document. Fix is to wrap the body in an IIFE.
