# 2026-10-17

## Fixed: Turbopack "Transforming CSS failed" in rack-01.module.css

`glass-instruments.patch` added a bare `[data-instrument-host] { isolation: isolate }`
rule to `features/landing-page/rack-01/rack-01.module.css`. Turbopack (Next 16.3.7)
rejects an impure selector in a CSS module — every selector must contain at least one
local class or id — so the whole landing page failed to build.

Fix: scope the rule to the two hosts it actually targets,

```css
.controller[data-instrument-host],
.cassetteDeck[data-instrument-host] { isolation: isolate; }
```

Both classes are already `position: relative`, which is what the instrument's
absolutely-positioned canvas needs, so no other change was required. The rest of the
patch's block is pure already (`[data-instrument='on'] .screwTopLeft` carries a local
class). `npx next build` passes.

Gotcha to remember: the bare-attribute selector is the one shape that cannot go in a
`*.module.css` — reach for `:global(...)` or hang the attribute off a local class.
