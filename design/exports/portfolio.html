A PORTFOLIO IN FOUR MOVEMENTS
Last year I built this portfolio in a rush. It worked, but the codebase was not something I was proud of — thirty dead component files, versioned names like hero-2025-v2.tsx that told a story of failed experiments, and a single data.ts containing projects, posts, links and experience in one 200-line export.
The problem
Every page had invented its own vocabulary. The blog used zinc utilities, projects used bg-card, bookmarks had a half-migrated token system. Nothing was wrong enough to break, which is exactly why it survived so long.
A portfolio is not a museum. If a component does not earn its place, it is weight.
What changed
I moved to a feature folder layout where each surface owns its components, styles and data access. The shared layer became three files: tokens, formatting, and the fetch helpers that every page already duplicated.

The unglamorous part was deleting things. Forty-one files went out, eleven came back. What replaced them is smaller, and every screen now speaks the same two typefaces and the same eight tokens.
